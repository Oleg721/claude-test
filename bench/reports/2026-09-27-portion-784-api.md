# Portion photos at 784 px on the Messages API — 2026-09-27

Question: with the photo kind chosen by a button in the app, can `/portion/photo` send half the label size?

Setup: prompt v5, `sonnet-low-nothink@anthropic` (Messages API), eight stills of the sixteen: four apples (314 / 242 /
113 / 127 g), two bananas (157 / 141 g), two mandarins (68 / 49 g). The full-size photos (4032 × 3024) went to the
endpoint; the server capped them at 784 px (`PORTION_MAX_EDGE_PX`), so the model saw 588 × 784. The 61° still was
left out: its error is the depth, not the image. Run: `bench/runs/2026-09-27-measure-v5-api-784`.

| apple on the table | 314 g | apple, whole, sphere | 341 (+9 %) |

- **Names 8 / 8**, and every gram equals the 1568 px Agent SDK run on the same stills (`2026-09-27-measure-v5`): the
  rows are the same, so the server's arithmetic is the same. MAPE 7 % on these eight.
- **Cost: $0.0058 a call**, flat (2 417 input tokens, 83–115 output, no retries). At 1568 px the image alone is
  ~2 350 visual tokens instead of 588, ~$0.009 a call: the half size saves about 40 %.
- **3.5 s a call** on average, 4.5 s at most.

Decision: `/portion/photo` caps photos at 784 px; `/nutrition/photo` (labels) stays at 1568 px, where the small print
needs it (`2026-09-27-resolution.md`).
